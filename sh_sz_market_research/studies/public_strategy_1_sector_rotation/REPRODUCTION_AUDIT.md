# 公开策略1源码复现与规则差异

## 结论

原仓库主结果可以大体复现，但不能按 README 的实盘描述直接采信。固定上游提交为 `ec1b5003284bc9d39de22d47e73d74efaec4740f`，使用源码重新下载数据并按 README 的 `vol_target=0.11` 运行后，2020-01-01—2026-04-21得到年化23.59%、最大回撤-6.87%、Sharpe 2.03。仓库README公布值为年化25.00%、最大回撤-6.87%、Sharpe 2.33。

回撤一致、年化相差1.41个百分点、Sharpe相差0.30。差异可能来自数据源历史值更新、截止日不同以及仓库内结果文件与当前脚本版本不完全同步。

## 原源码与README内部不一致

1. README称“周五收盘信号、下周一开盘执行”，实际代码在周五收盘数据上计算信号，并立即按同一个周五收盘价调仓。这个价格在完整计算收盘信号之前不可保证成交，属于乐观成交时点。
2. README主结果写波动目标11%，`scripts/run_v5i_final.py` 默认值却是13%；只有显式传入 `--vol_target 0.11` 才是README参数。
3. README主样本截至2026-04-23，当前一键脚本固定截至2026-04-21。
4. README把IS描述为2020—2023，一键脚本实际另跑的IS窗口是2018—2023。
5. `requirements.txt` 未声明源码必需的 `akshare` 依赖，无法按文档在干净环境直接运行。
6. 源码中还写入了一个默认Tushare令牌，而不是只从环境变量读取；复用代码前应删除并更换该凭据。
7. ETF池是事后整理的固定64只名单，虽然代码按上市历史动态准入，但主题选择本身使用了后见信息，仍存在ETF池选择偏差。
8. 原策略只使用后复权收盘价，没有开盘成交、停牌/涨跌停、买卖盘口和资金容量约束；0.05%单边成本明显低于本项目个股压力口径0.3%。

## 下一步建议

不要直接把原版23%—25%的年化当作沪深行业策略目标。下一步应在原ETF数据上只修正一项：把交易延迟到下一交易日，再分别测试原0.05%费用和0.30%压力费用。由此可以量化“同日收盘成交”和低费用分别贡献了多少。之后再决定是否将周频、真实行业分类和防御ETF篮子移植到沪深版本。

## 日线实盘限制复跑（2026-09-14）

已使用1000万元、2020-01-02—2026-07-31重新运行原策略信号结构，并加入日线可以验证的实盘限制：

- T日收盘形成信号，T+1开盘交易；
- ETF按100份整数手；
- 佣金万二、单笔最低5元，ETF不收印花税；
- 买卖双边0.2%滑点；
- 单只ETF单日成交量不超过市场成交量的5%；
- 无量、缺失开盘价视作停牌，不能交易；
- 一字涨停不能买、一字跌停不能卖；
- 未成交订单不假设瞬间完成，旧持仓继续保留；
- 防御、过热切换、11%组合波动目标和原策略ETF池保留。
