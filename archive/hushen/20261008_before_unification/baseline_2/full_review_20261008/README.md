## D7解决了什么

1. 原买限价向下取整可能吞掉低价股0.1%容差；改为买向上、卖向下按分取整，并限制在涨跌停价内。
2. 关闭平台额外滑点，避免用户日志中的限价之外再加记账价差；下单容差仍保留，关闭额外滑点不等于真实交易没有摩擦。
3. 买入资金预留考虑一分取整，不提前使用未成交卖单资金。沿用实际持仓/可卖数量、活动订单检查和每日一次执行。
4. 订单/成交回报去重，过时回报不能倒退订单状态；费用与限价异常输出FEE_MISMATCH/LIMIT_BREACH。确认成交穿越限价后停止后续新提交，需核对平台后重新启动；外来活动订单会被拒绝混入。费用告警不擅自修改账户。
5. 盘前打印墙钟、策略时钟和耗时，执行阶段记录时间，帮助区分平台调度延迟与计算耗时。
6. 失败订单不生成虚假持仓，剩余目标次日按新开盘价重新尝试，部分成交只补差额。无盘中撤改单、无隔夜手操、无三日强制过期。

**未保证解决的平台问题：** 限价单仍可能合理地不成交。旧日志没有当时盘口/撮合内部轨迹，五只零成交根因不能最终确定。公开API没有核实到独立修正平台印花税/过户费的方法，代码只告警，不更改平台现金。新平台真实回报到来前，不能宣称这些平台内部问题已实测消除。重复UI/传输层日志也不由策略完全控制。

## 本地撮合及成本

使用不复权价、前一日信息生成信号。日线按开盘撮合近似，先卖后买、买卖限价不得被穿透、T+1、整手与可卖数量、过去20日均量0.5%和100万股单笔上限、日成交量25%限制。0.1%价格冲击在限价及当日成交范围内约束。本地顺序卖出到账属于日线近似；盘口队列、盘中时序、实时价格笼子基准和网络延迟无法由日线确定。不能把本地零拒单理解成平台保证成交。

佣金万三最低5元；过户费2022-04-29前万0.2、之后万0.1；卖出印花税2023-08-28前千1、之后万5；公司行动、到账日期、送转股解锁及FIFO分红税沿用审计账本。费率为用户接受的研究假设，未核验国金账户合同。实际佣金含哪些规费必须以交割单为准；本地不重复添加已假设包含于佣金的规费。

净值包含期末持仓及应收分红，不强制平仓。Sharpe：日简单收益、样本标准差、252日、无风险利率0；年化：实际日历天数含首尾。手续费合计已经从资产扣除，不能再扣一次。未来退出成本/潜在未实现分红税不计入当前已实现费用。
