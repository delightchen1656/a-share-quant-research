# 公司行动精确去重：绩效前恢复协议

## 恢复原因与边界

- 第一次冻结执行在行情矩阵载入后、`ExecutionMarket` 构造期间停止；错误为同一股票、同一除权日出现第二条记录。账户模拟、主路径和任何收益指标均尚未开始。
- 原始失败证据保留为 `FROZEN_BEFORE_EVALUATION.json`、`RUN_STARTED.json` 和 `RUN_FAILED.json`；原冻结脚本 `run_once.py` 不修改。
- 恢复仍只读取 `inputs_pre2025/` 白名单，截止日仍为 2024-12-31；不读取任何受限目录、生产选择或边界后行情/结果。

## 唯一规范事件的证据

- 全部允许期内、有效原始股票的公司行动扫描只发现一组重复：`600660.SH / 2017-05-15`，来源键为 `600660.SH/2017` 与 `600660.SH/2023`。
- 两条记录的完整解析字典和规范 JSON 哈希完全相同；现金、送股、转增、登记日、除权日、支付日和上市日字段均无差异。经济含义是每股现金 0.75、送转 0，不能重复相加。
- 2017-05-12 实际收盘 23.08；`(23.08 - 0.75) / (1 + 0) = 22.33`，与 2017-05-15 白名单 `preclose=22.33` 完全一致，证明市场价格只反映一次该分配。
- 完整记录、字段、哈希和恒等式保存在 `ACTION_CANONICAL_DEDUP_AUDIT_BEFORE_RECOVERY.json`。原公司行动快照保持不变。

## 冻结的规范加载规则

1. 仍按来源键字典序和列表顺序读取；同一 `(symbol, dividOperateDate)` 首条记录成为规范事件。
2. 后续记录只有在完整解析字典与规范记录精确相同时才跳过，并计入审计；绝不把重复现金或股份相加。
3. 同一事件键只要出现任一字段差异，立即报错停止，不自行选取、拼接或推断。
4. 本次已知唯一重复因此保留 `600660.SH/2017`，跳过误分桶 `600660.SH/2023`。

## 策略与恢复执行不变性

- 四因子公式、精度、窗口、过滤、5只持仓、98%仓位、1.5缓冲、20交易日全局相位、初始资金、撮合、费用、税率、T+1、FIFO、日期范围、所有评价场景和门槛均与第一次冻结完全一致。
- 已锁定的信号缓存、三端点一致性结果和全部输入哈希直接复用，不重新计算或挑选信号。
- `canonical_action_recovery.py` 只导入原冻结模块并替换公司行动加载函数；它验证原冻结锁及本恢复锁后才允许一次执行。第一次尝试没有绩效，因此恢复运行是唯一一次绩效计算，不是第二个候选或参数重跑。
- 恢复代码、上述证据、原冻结锁及输入公司行动快照的哈希必须先写入 `FROZEN_BEFORE_CANONICAL_ACTION_RECOVERY.json`，再开始账户模拟。
